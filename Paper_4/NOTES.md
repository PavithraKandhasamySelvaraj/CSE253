## Off-policy result: Qwen2.5-7B-Instruct (run 2026-11-20, corrected 2026-11-27)

A Qwen2.5-7B probe trained on Instructed-Pairs scores **Apollo's 70B transcripts** with Apollo's
labels. The threshold comes from 1,000 of Apollo's **70B** Alpaca responses (also off-policy).
Layer 18 of 28 was selected by Roleplaying AUROC. All 29 probes converged.

| Dataset (H/A/D) | AUROC ours / 70B | recall@1% ours / 70B | honest FPR @1% ours / 70B | recall@0.25% ours |
|---|---|---|---|---|
| IP val (61/0/61) | 1.000 / 1.000 | 1.000 / 1.000 | 0.00 / 0.02 | 1.000 |
| Roleplaying (84/84/203) | 0.880 / 0.964 | 0.833 / 0.961 | 0.25 / 0.25 | 0.626 |
| IT Report (669/324/336) | 0.991 / 0.999 | 0.908 / 1.000 | 0.01 / 0.78 | 0.461 |
| IT Confirmation (24/2/630) | 0.775 / 0.974 | 0.973 / 0.994 | 0.83 / 0.50 | 0.451 |
| Sandbagging (511/64/420) | 0.996 / 0.983 | 1.000 / 0.998 | 0.47 / 0.50 | 0.998 |

AUROC against Alpaca: 0.987-0.999.

**Correction (2026-11-27).** The first version of these results used the wrong detect mask on all four
eval sets: 3 tokens left / 1 right everywhere. Apollo's padding differs by dataset (Llama left/right:
Roleplaying 0/0; Insider Trading and Sandbagging 0/1, because `base.py` zeroes `left` when reasoning
is trimmed; Alpaca 4/1). Confirmed in `example_results/instructed_pairs/detection_masks.html`.
Training and Alpaca masks were already right. Fixed by slicing the cached per-token scores: the new
mask equals the old one minus the extra tokens on all items (0 mismatches), and a GPU re-score of
4 items per eval set at layer 18 matched to <3e-6. Superseded numbers (layer 17) are not valid.

Gaps above about 5 points (agent.md §5). The causes are **hypotheses; none has been tested**:
- Roleplaying (AUROC -8, recall -13), IT Confirmation (AUROC -20), IT Report (recall -9).
- Candidates: smaller model; off-policy text (Qwen reads Llama-70B's responses and the threshold
  uses Llama-70B's Alpaca responses); a different chat template and padding analogue.
- IT Confirmation has only 24 honest items, so its AUROC is noisy (no confidence interval computed).

Layer sensitivity: AUROC peaks around layers 16-19. Recall moves much faster than AUROC: IT Report
recall@1% is 0.99 at layer 17, 0.91 at 18 and 0.00 at 20, while AUROC stays >=0.97 (the paper
reports the same kind of sensitivity). Layer 18 follows the pre-set rule; layer 17 has higher
Roleplaying and IT Report recall but was not chosen, to avoid picking on the reported metric.
Early layers are weak or inverted. Layer selection and reporting both use Roleplaying, so the
Roleplaying number is optimistic.

## Stage-1a: metric-code validation (no GPU)

`python -m src.p4.validate_released` recomputes Apollo's `example_results/instructed_pairs/results_table.csv`
(70B, layer 22) from their released per-token scores using **our** `src/common/metrics.py`.

RESULT (2026-11-20): **max |ours − released| = 2.2e-08** over all 9 datasets × 9 columns (float32
rounding). Paper Table AUROCs reproduced: Roleplaying 0.9637, IT-Report 0.9985, IT-Confirmation 0.9745,
Sandbagging 0.9832. Loader counts also match the paper exactly (84/84/203, 669/324/336, 24/2/630,
511/64/420, 9,994 Alpaca).

Gotcha found: Apollo's `results_table.csv` column "recall 0.2%" is really **FPR = 0.25%**
(`f"{0.0025:.1%}"` → "0.2%"). Our metrics label it "0.25%".

Note from that table: at the Alpaca-calibrated 1% threshold, the **in-dataset honest FPR is high**
(Roleplaying 25%, Insider-Trading Report 78%, Sandbagging 50%). "Recall >96% at 1% FPR" is 1% FPR
on Alpaca, not on honest items of the same task. This matters for our benchmark port (§3 uses the
same Alpaca procedure) — report both.

## Our choices (not from paper or repo)

| Choice | Value | Why |
|---|---|---|
| Activation capture | forward hooks on decoder blocks, not `output_hidden_states` | 12 GB GPU; skips LM head + remaining blocks. Identical to HF `hidden_states[l]` for l < L |
| Chat rendering | model's own `apply_chat_template`; Llama `date_string="26 Jul 2024"` (matches released transcripts) | model-agnostic for Qwen |
| Qwen detect padding | left 3 (`<\|im_start\|>assistant\n`), right 1 (`<\|im_end\|>`) | analogue of Apollo's llama tokens; a side Apollo sets to 0 stays 0 (`family_pad`) |
| Layer selection (8B) | sweep all layers (29 on Qwen2.5-7B); pick max Roleplaying AUROC, tie → recall@1% | paper: "sweep on Roleplaying"; exact criterion unstated |
| Control set size | 1,000 Alpaca (paper 10k) | agent.md §4.4 |
| Precision on 12 GB GPU | bf16 + CPU offload (`--gpu-mem-gib 9`), not quantization | keeps activations exact; slower |
| No default system prompt for Llama | Llama-3.1 template already inserts its date block | Apollo's `ensure_system_prompt` path not reproduced |

## Stage-1 plan for 8B (paper has no <70B results)

1. **1b/1c off-policy (implemented):** train 8B probe on Instructed-Pairs, score Apollo's **released 70B
   transcripts** with their labels. Isolates "does the probe direction transfer to 8B" from "does the 8B
   model actually deceive". Off-policy is a deviation: the paper's main results are on-policy.
2. **1d on-policy (todo):** regenerate Roleplaying (371 scenarios in `data/roleplaying/dataset.yaml`) and
   Sandbagging (programmatic labels) with 8B, greedy; label Roleplaying with the local judge using
   `data/roleplaying/grading_template.txt`. Insider Trading needs the multi-step agent scaffold in
   `scripts/generate_insider_trading_transcripts.py` — heaviest, do last. Expect far fewer deceptive
   items from an 8B model; class counts will differ from 84/84/203 etc.
3. Black-box baseline: `data/black_box_baseline/prompt.txt` on the local judge; recompute its 1% FPR
   threshold on our Alpaca control (don't reuse "≥6").

## Source discrepancies to know about

- Black-box monitor prompt: paper App. G.4 prints a **binary** (honest/deceptive) version, while its
  §4.2 and the repo's `data/black_box_baseline/prompt.txt` use a **1-7 scale**. agent.md points to
  App. G.4; use the repo file.
- "Last 5 tokens excluded" (paper, agent.md) is last 5 **words** in the code.
